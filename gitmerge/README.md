# gitmerge

使用 Go 开发的批量分支合并工具。先用 `git merge-tree` 检查所有目标分支，全部通过后，在临时 worktree 中依次合并、推送，并拉取更新本地同名目标分支。

## 构建

不使用 Go module，按 GOPATH 模式构建，仅依赖公开模块 `golang.org/x/net/context`。需要 Go 1.17 及以上，以及支持 `git merge-tree --write-tree` 的 Git（建议 2.38 及以上）。

在仓库根目录执行：

```powershell
cd gitmerge
go build -o gitmerge.exe
```

如环境已设置 `GO111MODULE=on`，构建前改为 `off`（或临时 `$env:GO111MODULE = 'off'`），否则 Go 会在当前目录找不到 `go.mod` 而报错。

将 `gitmerge.exe` 所在目录加入 `PATH`，即可在需要合并的 Git 仓库中使用。

## 用法

```text
gitmerge a b c d
gitmerge --remote upstream a b c d
gitmerge --help
```

第一个分支是源分支，后续分支都是目标分支；示例表示将 `a` 分别合并到 `b`、`c`、`d`，每合并完一个目标就立即推送，然后在临时 worktree 中执行 `git pull --ff-only` 更新本地同名分支。`--remote` 必须放在分支参数之前，默认是 `origin`。

## 执行规则

- 源分支优先取本地已提交的版本，本地不存在时取远端版本。未提交的工作区修改不会被带入合并；本地源分支存在时，不会自动拉取或合并远端源分支的更新。
- 所有目标分支必须已存在于远端，并以实际推送地址上的最新提交为合并起点。本地同名分支的未推送提交不会被带入远端合并。
- 先读取远端分支到本次运行专用的临时引用，不更新当前仓库的 `FETCH_HEAD` 或远端跟踪分支。
- 对全部目标执行 `git merge-tree --write-tree --name-only --messages -z`。有任何冲突、目标不存在或检查失败，均不执行任何合并或推送；逐个列出失败分支、冲突文件及详情。
- 全部检查通过后，在系统临时目录建立 detached worktree，使用 `ort` 策略合并。可快进时快进，否则生成中文说明的合并提交。
- 每个目标合并后核对结果与预检查一致，再普通推送到对应远端分支；不强制推送。远端并发变更导致非快进、权限不足或钩子拒绝等情况会停止后续操作。
- 每个目标推送成功后，复用临时 worktree 检出本地同名目标分支，执行 `git pull --ff-only --no-rebase`，并更新对应的远端跟踪引用。拉取使用本次指定远端的实际推送地址及同名分支，不依赖本地分支原有的 upstream 配置。
- 本地目标分支不存在时不创建新分支，提示并跳过本地更新；目标分支正在当前工作目录或其他 worktree 中使用时也会跳过，并提示需要手动拉取的路径。其远端合并和推送仍正常执行。
- 本地分支有额外提交时会保留这些提交；本地与远端分叉而无法快进时，本地拉取失败并停止后续目标，不执行强制重置或变基。该目标已成功推送的远端结果会保留。
- 每个目标完成后移除临时 worktree；流程退出时再次清理 worktree、临时目录和临时引用，包括可处理的 Ctrl+C。不会切换当前工作目录的分支，不要求当前工作区干净，也不会修改已有工作区中的文件。
- 多分支推送不是事务：前面的目标已推送成功时，后续失败不会回滚前面的远端变更。输出会分别列出已推送、本地已拉取及跳过本地更新的目标，修复问题后可重新运行。

正常完成和可处理的失败都会清理资源。如果进程被强制终止、机器断电或文件被占用，清理可能无法完成；清理失败时会报告路径。清理仅针对本次运行创建的 worktree 和临时引用，不清理其他 worktree。
